# Глобальные настройки и профили книг

> Статус: основная реализация интегрирована в рабочем дереве и прошла автоматические проверки. Продуктовые решения согласованы, включая единый text connection и вариант A для новых чатов. Ручная браузерная/мобильная проверка и recovery UI для legacy connections остаются отдельной работой.
> Дата сверки: 2026-10-04.
> Основание: подтверждённые решения пользователя и чтение текущего кода рабочего дерева, не только `main`.
> Проверка 2026-10-04: `npm run build` успешно; защищённый `npm test` — 616/616 тестов в 115 файлах, concurrency=1, пик всего дерева процессов 399 МиБ при лимите 2 ГиБ без swap. `git diff --check` успешно. Ручная браузерная проверка не выполнялась.

## 1. Зачем меняем

Прежнее левое пространство настроек совмещало параметры текущей книги, глобальные предпочтения устройства и конфигурацию внешних сервисов. При расширении приложения эта структура стала слишком тяжёлой и неочевидной.

Целевая модель:

- **Глобальные настройки** — место, где создаются и редактируются подключения, профили моделей, пресеты промптов и профили интерфейса.
- **Книга** — место, где выбираются уже созданные профили и пресеты и настраивается рабочий контекст.
- **Профиль** — общий именованный объект, а не копия настроек внутри каждой книги. Редактирование модельного профиля изменяет конфигурацию всех связанных книг.
- **Подключение** — глобальная техническая конфигурация сервиса. Ключи не редактируются и не хранятся отдельно для каждой книги.

Перестройка касается левого пространства настроек и глобальных Settings. Правое пространство Book / Outline / Notes / Codex / Chat, данные книги и основной редактор сохраняют своё назначение.

## 2. Что уже задано пользователем

Следующие требования считаем исходными, а не вопросами на повторное согласование:

1. Подробные AI-настройки выносятся из книги в глобальные Settings, доступные из Home.
2. Connections не требуют книжных профилей: сервисы и credentials настраиваются глобально, с возможностью отдельного подключения для speech и других назначений.
3. Для моделей нужны общие редактируемые профили. Книги ссылаются на выбранный профиль; его изменения распространяются на связанные книги.
4. Main context cap и Codex model context cap нужно перенести из общего Advanced в карточки соответствующих моделей.
5. Промпты редактируются глобально; в книге выбираются пресеты, а не настраиваются полные композиции.
6. Context остаётся рабочей настройкой текущей книги/чата.
7. Audio cache — глобальная настройка, без книжных вариантов конфигурации.
8. Speech credentials и provider API keys для изображений объединяются с AI Connections.
9. TTS и STT становятся типами моделей в AI Models, вместе со своими параметрами.
10. Тема, типографика и настройки Editor собираются в UI-профили, выбираемые книгой.
11. Наборы favorite models для изображений оформляются профилями, создаваемыми глобально и выбираемыми книгой.
12. В левом пространстве книги остаются две вкладки: **Profiles** и **Context**.
13. Рядом с Home в левом пространстве нужна кнопка глобальных Settings.
14. Рядом с выбором каждого профиля/пресета нужна короткая ссылка **Edit**, открывающая именно этот объект в глобальных Settings.
15. В хедере глобальных Settings нужна кнопка **Back to last book**.
16. `Read aloud after generation` пока редактируется глобально. Быстрый книжный переключатель можно добавить позже.
17. Один text profile содержит все текстовые роли, настраиваемые по отдельности. Добавляется отдельная роль Character chat.
18. TTS, STT, **Image и Video** имеют отдельные типы профилей; UI — также отдельный профиль.
19. Prompt presets — живые ссылки для книг; независимый вариант создаётся через Duplicate.
20. Text reveal speed входит в UI profile; Response length — в соответствующий prompt preset.
21. Чат сохраняет собственный снимок начальной конфигурации. Дальнейшее редактирование глобальных профилей/presets не меняет уже созданный чат; ручные настройки внутри чата остаются.
22. В глобальных Settings выбираются defaults для новых книг и работы вне книги. Default UI profile используется на Home и остальных глобальных экранах.
23. Для каждого типа существует доступный default profile/preset, защищённый от удаления. Можно назначить другой default; прежний можно удалить только при отсутствии живых ссылок.
24. Общие профили/presets сохраняются явной кнопкой Save с предупреждением о связанных книгах.
25. Backup не содержит **ни ключей, ни конфигураций connections**, включая endpoints, accounts, локальные connection IDs и credential/connection fingerprints. Профильные определения без подключений остаются переносимыми в `.arcbook` v4.
26. Глобально активен **один text provider/connection для всех text profiles и ролей**; выбора connection внутри text profile нет.
27. Новый Chat/Character chat получает snapshot соответствующей роли из **text profile, выбранного книгой (вариант A)**, не из глобального default text profile. Отдельного книжного Chat selector нет.

## 3. Что существует сейчас

Ниже — контракт текущего рабочего дерева. Автоматические проверки прошли; границы и дополнительные ручные проверки отмечены отдельно.

| Область | Сейчас в коде | Граница / дальнейшая проверка |
| --- | --- | --- |
| Навигация настроек | Книга видит Profiles + Context; глобальные Settings — AI / UI / Application / Sync; выборы имеют Edit | Проверить guards, мобильные переходы и сохранение drafts |
| AI / Connections | Книга хранит IDs профилей; `resolveProfileSettings()` подставляет единую активную глобальную text connection | Смена provider не переводит автоматически сохранённые model IDs; локальная настройка должна быть совместимой |
| Text models / caps | Main, Support, Codex, Chat, Character chat в одном профиле; Main/Codex caps в карточках ролей | Проверить fallback и hard limits у всех runtime-потребителей |
| Prompt presets | Story/Codex/Summary — живые книжные ссылки; Chat/Character presets выбираются в text profile | Legacy Apply — не контракт книжного выбора; проверить валидацию и previews |
| Save | Черновик, список связанных книг, явный Save и подтверждение; Duplicate; запрет удаления default/используемого объекта | Проверить ошибки хранения и одновременные редакторы |
| Speech / media | Отдельные TTS, STT, Image и Video profiles; credentials только в Connections; audio cache в Application | Поддержка остаётся ограниченной существующими адаптерами |
| UI / defaults | Книга выбирает UI; глобальные поверхности используют default UI; reveal speed в UI, response length в presets | Новая книга получает IDs defaults, не независимую копию настроек |
| Chat | `createChat()` снимает роль из выбранного книгой text profile; отдельная Character role; свои model/thinking/prompt/limits/context | Existing chats/forks сохраняют snapshots; connection остаётся глобальной и не фиксируется в чате |
| Backup / sync | `.arcbook` v4 включает выбранные определения и зависимости; очистка connections; import remaps IDs, sync-конфликты профилей клонируются при установке | Проверить старые версии, повторные pulls и сбои между localStorage и IndexedDB |

Известные ограничения сверки:

- Миграция сохраняет старые книжные AI settings в локальном `meta` и создаёт/переиспользует безопасные профили, но **не переносит различающиеся старые credentials в активные Connections**. `readPreservedBookAiSettings()` существует без вызывающего UI; пользовательского экрана сопоставления/восстановления пока нет. Поэтому сохранность recovery data не равна сохранению прежнего рабочего подключения каждой книги.
- Библиотека профилей хранится в `localStorage`, а книги — в IndexedDB. Импорт может установить новые профили до ошибки/rollback книжной транзакции; нельзя обещать атомарный rollback обоих хранилищ. У connected sync определения устанавливаются лениво при чтении книжных selections.
- Last-book state сохраняет book/document/chat IDs и editor/chat surface, **не** cursor/scroll/focus. Это не полное восстановление рабочей позиции.
- UI-профиль сейчас содержит собственный `customThemes`, а не ссылку на отдельную общую библиотеку тем. Это детализация реализации, отличающаяся от рекомендации раздела 5.7.

README и `PRODUCT_SPEC.md` отражают этот контракт с оговоркой о незавершённой интеграции.

## 4. Согласованная структура экранов

Разделение уровней и основные секции согласованы и представлены в текущем коде. Схема ниже — контракт, не отметка о завершённой UX-проверке.

### 4.1. Глобальные Settings

```text
Settings
├── AI
│   ├── Connections
│   ├── Models
│   │   ├── Text profiles
│   │   ├── Text-to-speech profiles
│   │   ├── Speech-to-text profiles
│   │   ├── Image profiles
│   │   └── Video profiles
│   └── Prompts
│       ├── Story presets
│       ├── Codex presets
│       ├── Summary presets
│       ├── Chat presets
│       └── Character chat presets
├── UI
│   └── UI profiles: Theme / Typography / Editor
├── Application
│   ├── Audio cache
│   ├── Defaults: новые книги и работа вне книги
│   └── Context defaults for new books
└── Sync
```

Не обязательно показывать всё дерево одновременно: AI и UI могут использовать существующие внутренние tabs/sections и селектор профиля.

- Connections — единое место для credentials всех поддерживаемых AI-сервисов.
- Images и Speech больше не дублируют панели credentials.
- Audio cache не является модельным профилем. Его можно разместить в Application или в отдельной глобальной секции Audio; это вопрос компоновки, не изменения области действия.
- Существующие глобальные Context defaults можно сохранить как начальные значения новых книг. Они не должны превращать рабочий Context книги в общий связанный профиль.
- Sync остаётся глобальным и не относится к AI Connections.

### 4.2. Левое пространство книги

```text
[Home] [Global Settings]                         [Close]

Profiles
Context
```

**Profiles** содержит только выборы, краткое описание эффективной конфигурации и переходы к редакторам:

```text
Text models         [Writing · balanced       ▾] [Edit]
Story prompt        [Story · restrained       ▾] [Edit]
Codex prompt        [Codex · structured       ▾] [Edit]
Summary prompt      [Summary · concise        ▾] [Edit]
Text to speech      [Narrator                 ▾] [Edit]
Speech to text      [Dictation                ▾] [Edit]
Images              [Illustrations            ▾] [Edit]
Video               [Cinematic                ▾] [Edit]
UI                  [Quiet writing            ▾] [Edit]
```

Названия приведены как примеры, не обязательные встроенные профили. Отдельного книжного выбора Chat prompt нет: начальный preset задаётся в роли Chat/Character chat выбранного книгой text profile и копируется при создании чата (вариант A).

В Profiles **не должно быть** API keys, endpoint inputs, каталогов моделей для детальной настройки, полного редактора промпта, параметров шрифта или палитры.

Можно показать read-only summary: какие модели входят в text profile, какой voice выбран, какая тема используется. Это помогает понять выбор без похода в редактор.

**Context** сохраняет рабочее назначение: источники и режимы контекста, текущие книжные/чатовые настройки, бюджет и request preview. Бюджет и preview используют эффективные модели и промпты выбранных профилей.

## 5. Глобальные объекты и их границы

### 5.1. Connections

Пользователь выбрал простую глобальную конфигурацию провайдеров, без библиотеки именованных подключений одного provider и без разных подключений для текстовых профилей/ролей.

- Credentials и endpoint/base URL задаются глобально для провайдера.
- `Active text provider` выбирает рабочее text-подключение. Отдельный `Connection provider` переключает **всю группу полей** редактируемого провайдера, не активируя его: основной API key, поддерживаемые speech/media overrides и endpoint. OpenAI и NanoGPT показывают только свои ключи; LiteLLM — основной ключ, base URL и Pruna / LiteLLM media override. OpenRouter и OpenAI-compatible не показывают неподдерживаемые speech/media поля; Fake показывает локальную диагностику вместо credentials. Название провайдера видно в заголовке группы и лейбле основного ключа. Переключение групп сохраняет черновики; `Save connections` записывает все изменения, `Discard` отменяет их.
- Одни настройки провайдера могут обслуживать text, speech, images и video, если это поддерживается реализованными адаптерами. Например, один OpenAI key используется для text и images.
- Предусмотренная ранее возможность глобального speech override не означает появления книжных overrides или нескольких text connections.
- Профили не содержат ключей; книга не выбирает credentials напрямую.
- Не расширяем поддержку провайдеров автоматически: объединение UI не означает, что любой text endpoint начинает поддерживать speech или images.

**Подтверждено:** один глобально активный text provider/connection обслуживает **все text profiles и все их роли**, включая существующие чаты. Text profile не выбирает connection. В коде resolver берёт `provider`, `apiKey`, `baseUrl` и `providerProfiles` из глобальных настроек, не из профиля. В моделях других типов provider определяется выбранной моделью и использует глобальные настройки этого provider; поддерживаются глобальные speech/media credential overrides, но не книжные подключения.

Credentials, endpoints и вся конфигурация connections исключаются из backup и archive sync. Импортированные модели связываются с локальной настройкой провайдера; если её нет, показывается Setup required.

### 5.2. Text model profile

**Согласованная гранулярность:** один профиль содержит набор ролей **Main / Support / Codex / Chat / Character chat**. Модель и параметры каждой роли настраиваются отдельно; книга выбирает один text profile. TTS, STT, Image и Video имеют отдельные типы профилей.

Это близко к нынешнему устройству Models и не связывает смену модели письма со сменой голоса или визуального набора.

Для каждой text-роли профиль хранит:

- выбранную модель;
- thinking effort;
- относящиеся к этой роли параметры и лимиты.

В карточке Main находится `Story / Main context cap`; в карточке Codex — `Codex model context cap`. Рядом показывается известный максимум модели и пояснение эффективного лимита.

- Пользовательский cap не повышает жёсткий максимум модели.
- Пустой cap означает существующее поведение без дополнительного пользовательского ограничения.
- При fallback Codex → Main явно показывается, что действует Main cap.
- Известный context length модели — метаданные каталога; это не то же самое, что пользовательский cap.
- Не добавляем новые caps для Support и других ролей только ради симметрии. Существующие лимиты чата учитываем отдельно при согласовании его наследования.
- Существующие правила fallback сохраняем и показываем, а не меняем молча при перестройке UI.

Chat max model rounds размещается в карточке Chat; Character chat имеет собственные модельные настройки, чтобы не менять обычного помощника ради roleplay. Для Chat и Character chat также задаётся начальный prompt через выбор глобального preset. При создании чата копируется содержимое preset, а не живая ссылка на него.

Разные connections по текстовым ролям/профилям не вводятся. Роли Chat/Character chat при создании берутся из text profile **выбранной книги**, не из глобального default text profile (вариант A).

### 5.3. Prompt presets

Отдельные библиотеки по назначению: Story, Codex, Summary, Chat и Character chat. Для нового character preset нужно сохранить специальные roleplay-переменные и ограничения текущего character-chat режима.

Preset содержит название, scope и композицию: system prompt + упорядоченные predefined messages. Сохраняются валидация шаблонов, переменные, preview и существующие возможности редактирования.

**Согласовано:** выбор книги является живой ссылкой на preset, аналогично модельным профилям. При необходимости независимого варианта пользователь делает Duplicate в глобальной библиотеке и выбирает копию. Исключение — уже созданные чаты: их prompt хранится как независимый снимок.

В текущем resolver живые ссылки уже реализованы. Старый Apply копировал содержимое и не определяет новую семантику книжного выбора.

- Duplicate создаёт независимый вариант. Рекомендация делать встроенные presets неизменяемыми не является подтверждённой реализацией: текущие default presets редактируемы и защищены от удаления, а не от Save.
- Книга выбирает отдельный preset для Story, Codex и Summary. Chat/Character chat presets задаются в глобальной конфигурации соответствующих ролей, не отдельным книжным выбором.
- Книжные переменные продолжают подставляться при сборке запроса. Общий preset не содержит зафиксированный текст чужой книги.
- Preview из книжного Edit может использовать текущую книгу как образец, но эта книга не становится частью сохраняемого preset.
- Рабочие инструкции Arc, содержимое сцен, lore templates и контекст не превращаются в глобальные presets в рамках этой задачи.

**Response length:** входит в соответствующий preset Story/Codex/Summary; resolver и глобальный редактор уже используют эту схему. Книга только выбирает preset. `{{response.length}}` отправляется лишь там, где enabled template ссылается на переменную: скрытой инструкции о длине нет.

### 5.4. TTS profile

- Provider выбранной модели; credentials берутся из глобальных Connections.
- Модель.
- Voice.
- Maximum parallel TTS requests.
- `Read aloud after generation`.

На первом этапе checkbox редактируется в глобальном редакторе TTS-профиля, а в книге меняется выбор профиля. Не добавляем книжный override в этой итерации.

Недоступная модель или voice не заменяются молча другим платным вариантом.

### 5.5. STT profile

- Provider выбранной модели транскрипции; credentials берутся из глобальных Connections.
- Модель.
- Language hint.
- `Stream text while speaking`, только если это поддерживает выбранная модель.

Сохраняются нынешние различия file/live transcription, permissions и правила обработки записей. Объединение настроек не означает, что возможности разных провайдеров совпадают.

### 5.6. Отдельные Image и Video profiles

**Согласовано:** это два независимых типа профилей, а не один общий image/video profile. Каждый содержит набор favorite models для своего типа генерации, а не credentials:

- устойчивый ID каждой записи набора;
- provider и provider model ID;
- имя/alias;
- поддерживаемые задачи своего типа;
- существующие настройки размеров, соотношений, quality, moderation и прочие модельные параметры;
- default models по задачам, где это уже поддерживается.

Credentials берутся из глобальных Connections соответствующего provider. Модель, поддерживающую image и video, можно включить в оба набора, без потери существующих возможностей.

Рабочие prompt, source image, параметры конкретного запуска, gallery и jobs остаются в Images workspace. Убираем оттуда дублирующее редактирование глобальных credentials/наборов: вместо него — ссылка в Settings на нужный профиль.

Images workspace, открытый из Home без книги, использует глобальные default Image и Video profiles, те же, которые назначаются новым книгам. Не подставляем незаметно профили последней книги.

### 5.7. UI profile

- Выбранная тема.
- Типографика основного редактора.
- Типографика расширяемых текстовых inputs.
- Highlight dialogue.
- Show scene beats.
- Save Arc as beat.

Включение `Save Arc as beat` соответствует предложению пользователя, но важно показать: оно влияет не только на внешний вид, а на сохранение инструкции как scene beat.

Первоначальная рекомендация — отдельная библиотека custom themes со ссылками из профилей. Текущая реализация хранит `customThemes` внутри UI-профиля, вместе с `activeThemeId`; sanitizer проверяет наличие выбранной темы. Не описываем отдельную общую библиотеку тем как уже реализованную.

**Text reveal speed:** вместе с Custom reveal speed находится в редакторе UI profile; resolver берёт задержку из выбранного UI, не из text model profile.

**Вне книги:** Home, глобальные Settings и остальные глобальные поверхности используют тот же default UI profile, который назначается новым книгам. Дополнительного независимого application UI profile не нужно. В книге применяется её выбранный профиль. В редакторе UI-профиля нужен preview черновых правок до Save.

## 6. Поведение общих профилей

Следующие правила задают контракт; наличие соответствующих путей в коде не заменяет проверку критериев готовности:

1. Создание, переименование, Duplicate и редактирование происходят только в глобальных Settings.
2. Переименование не меняет ссылки книг: связь строится по ID, не по имени, alias или ID модели провайдера.
3. В редакторе показывается «Используется в N книгах» и доступен список этих книг.
4. Для общих профилей/presets согласован явный **Save** с предупреждением о связанных книгах: черновые правки не распространяются до успешного сохранения. В текущем редакторе это уже представлено; книжные selections и рабочий Context сохраняются отдельно и не становятся общими черновиками.
5. После Save связанные книги используют новое значение без необходимости заново выбирать профиль или перезагружать приложение.
6. Уже запущенная генерация/транскрипция/озвучивание работает с зафиксированной конфигурацией. Изменения относятся к следующей операции, не к следующим tool rounds уже начатого ответа.
7. Image/video job фиксирует модельные параметры и локальную идентичность connection при создании. В коде это `localConnectionFingerprint`, не ID именованного подключения; credentials фиксируются на время выполнения. Продолжение provider job не должно незаметно переходить на другой account/endpoint. Fingerprint и provider ticket не переносимы и исключаются из archive.
8. Недоступный connection/profile/preset даёт понятную ошибку и Edit/Setup action. Нет тихой замены провайдера или платной модели.
9. Удаление используемого профиля запрещено без явного выбора совместимой замены для всех живых ссылок. Уже созданный чат хранит снимок и не зависит от существования исходного профиля/preset.
10. Если книга должна отличаться от остальных, пользователь делает Duplicate и назначает новый профиль. Скрытые книжные overrides не создаются.
11. Глобальные defaults — набор выбранных IDs для новых книг и работы вне книги. Новая книга сохраняет эти назначения. Смена default ID не переназначает старые книги; правка самого общего профиля влияет на все его книги, но не на сохранённые снимки чатов.
12. Для каждого типа всегда существует default profile/preset, защищённый от удаления. Можно назначить default другой объект; после этого прежний можно удалить при отсутствии живых ссылок. Пустая библиотека не допускается.

Пример: книги A и B выбирают `Writing · balanced`. Изменение Main model в этом профиле применяется к обеим. Если B нужна другая модель, создаём `Writing · B` и назначаем её книге B.

### Компактный хедер и явная область действия — контракт интеграции

- `.profile-library-controls` остаётся компактным блоком: `.profile-header-main` содержит selector, primary **Duplicate** и существующий shared `ActionMenu`. Rename/Create/Set as default/Delete переходят в это меню; `.profile-management-fields` с полем и Done либо Create/Cancel раскрывается только после выбора Rename/Create. На ширине ≤700px selector занимает отдельную полную строку; интерактивные цели — не менее 44px. `.profile-save-bar` не меняется.
- `.profile-header-meta` показывает **Shared profile**, при необходимости **Default** и `details.profile-usage` с **Used in N books**. Раскрытый список остаётся в потоке, не floating popover. При loading/error показывается соответствующее состояние без недостоверного счётчика. `.profile-linked-warning` явно объясняет глобальную область и время применения: параметры генерации — со следующей операции, Chat/Character presets — для новых чатов, UI — сразу на активных поверхностях с этим профилем. Существующие чаты сохраняют снимки моделей и промптов; источник книги виден также в `.profile-origin-note`, если переход был из книги.
- Duplicate копирует **сохранённую конфигурацию** после существующего save/discard guard; не назначает копию книге и не меняет defaults. `p.profile-copy-notice[role="status"]` сообщает о создании самостоятельной копии и предлагает явно назначить её: для обычных профилей — в Book Profiles, для Chat/Character presets — в соответствующей роли Text models profile (для независимости книги нужно также скопировать и назначить Text models profile). После Create/Duplicate фокус возвращается в постоянный selector. `details.profile-about` (**About shared profiles**) содержит пояснения о defaults, защищённом default и отсутствии скрытых книжных overrides.
- `nav.settings-breadcrumbs[aria-label="Settings location"]` содержит `ol > li` с простым текстом, последний уровень — `aria-current="page"`; все уровни, включая длинные имена, переносятся, а разделительные chevrons рисуются только CSS. Breadcrumbs и книжный источник остаются видимыми. Над книжными Profiles/Context расположен `.settings-book-scope`: breadcrumb и `p.profile-help`. Для Profiles: **Profile assignments apply only to this book. Editing a shared profile can affect other books.** Для Context — явное пояснение локальной области книги.

## 7. Навигация и возврат

### Входы

- Home → глобальные Settings.
- Книга → левое пространство → Global Settings рядом с Home.
- Книга → Profiles → Edit → глобальный редактор конкретного объекта.
- Images → Settings/Edit → глобальный редактор соответствующего image/video profile, без потери рабочего draft.

### Возврат

- В хедере глобальных Settings: **Back to last book** с названием книги, если она доступна.
- При прямом входе из книги возвращаемся в ту же книгу и рабочую поверхность: editor/document либо chat/conversation. По возможности восстанавливаем позицию и фокус.
- При входе через Edit дополнительно нужен **Back to Profiles**: возвращает к назначениям той же книги. Это не та же операция, что возврат прямо в редактор.
- Обычный Back/Close учитывает источник перехода, в том числе Home и Images.
- Home всегда ведёт в библиотеку.
- Если последняя книга удалена или ещё ни одна не открывалась, Back to last book скрыт либо недоступен с понятным пояснением.

В коде `last-book.ts` хранит последнюю книгу, editor/chat surface и document/chat IDs в `localStorage` между перезапусками; `updatedAt` не используется для этого выбора. `returnToLastBook()` проверяет наличие книги/документа/чата, недоступную книгу удаляет из предпочтения; при недоступном чате/документе остаётся fallback в editor. Close возвращается к исходному экрану, Back to Profiles — к назначениям книги. Cursor/scroll/focus в persisted state не входят; их полное восстановление остаётся непроверенным требованием.

Переходы должны проходить через существующие save/navigation guards. Несохранённый manuscript, активная генерация и ошибка сохранения настроек не должны теряться из-за новых кнопок. На первом этапе сохраняем нынешние ограничения на выход во время активной операции, а не меняем её жизненный цикл вместе с настройками.

На мобильном остаётся полноценный переход между поверхностями, без требования одновременно показывать два сайдбара и новый экран Settings.

## 8. Чаты: сохранённые снимки, не живое наследование

### Текущее поведение, проверенное в коде

`createChat()` разрешает **text profile выбранной книги** и копирует роль Chat: model (либо Main fallback), thinking effort, содержимое связанного Chat preset, model context length, effective context limit и max model rounds. Контекст берётся из книжных Chat context defaults. При Main fallback применяется Main cap; thinking и rounds остаются параметрами роли Chat. Эти значения сохраняются в сущности чата и доступны для ручного изменения.

`createCharacterChat()` вызывает тот же путь с ролью `character`: отдельные model/thinking/rounds и Character preset из выбранного книгой text profile. Участники, story cutoff и начальный character context фиксируются при создании; restart может передать существующие prompt/context явно. Ограничения знания и app-owned character instructions действуют отдельно от preset.

Credentials и connection не копируются в чат: при запросе runtime использует глобально активную text connection. Snapshot model/prompt не означает привязку к прежнему provider/account; смена активного provider требует совместимого model ID.

### Согласованное целевое поведение

- Новый обычный чат получает **снимок** конфигурации роли Chat, включая содержимое выбранного prompt preset и thinking.
- Новый character chat получает снимок отдельной роли **Character chat**, со своей моделью, thinking и начальным prompt.
- После создания изменение глобального model profile/prompt preset не меняет уже существующий чат.
- Повторное открытие сохраняет его выбранные настройки; нынешние ручные настройки внутри чата остаются.
- Контекст, участники и story cutoff остаются локальными рабочими данными.
- Никаких API keys/endpoint overrides внутри чата не появляется.
- При миграции существующие модели, prompts, thinking и лимиты чатов сохраняются без замены defaults.
- Специальные character инструкции, ограничения знания и правила доступа к story context сохраняются независимо от выбора модели.

**Источник подтверждён: вариант A — выбранный книгой text profile.** Глобальный default text profile назначается новой книге, но не обходит её последующий выбор. Отдельный книжный Chat prompt/default selector не вводится.

## 9. Концептуальная модель данных

Это границы сущностей, не финальные TypeScript types и не выбор конкретных таблиц.

```text
Global library
  Connections (global provider configuration; local-only)
  TextModelProfiles (Main / Support / Codex / Chat / Character chat)
    Chat / Character chat: initial prompt preset selections
  TtsProfiles (model + provider → global credentials)
  SttProfiles (model + provider → global credentials)
  ImageProfiles (image model entries → global provider credentials)
  VideoProfiles (video model entries → global provider credentials)
  PromptPresets (scope + composition + response length where applicable)
  UiProfiles → theme library
  ApplicationSettings (cache, default selections, navigation preferences)

Book
  ProfileSelections
    textModelProfileId
    ttsProfileId
    sttProfileId
    imageProfileId
    videoProfileId
    uiProfileId
    promptPresetIds: story / codex / summary
  ContextSettings (book-local)
  Book metadata and content (unchanged)
  Chats
    Independent saved model / thinking / prompt / limits
    Context and character configuration
    No credentials
```

Нужен единый resolver эффективных настроек, используемый Story, Codex, summaries/titles, quick tools, Chat, speech, illustrations и Images. Он соединяет книжные IDs, глобальные определения и локальные credentials; старый runtime shape при необходимости можно собирать на адаптационном слое.

Текущий адаптер `getBookAiSettings()` собирает прежний runtime shape из selections, профилей и Connections. `saveBookAiSettings()` теперь сохраняет только подходящие catalog context-length metadata в книжном records, не редактирует общий профиль. Полноту перехода всех потребителей ещё нужно проверить.

«Глобальные» здесь значит общие для книг в текущем приложении/браузере. Это не обещание автоматической синхронизации библиотеки между устройствами.

## 10. Миграция, backup и sync

### 10.1. Сохранить фактическую конфигурацию

- Миграция версионируется и допускает безопасный повтор после прерывания.
- Старые данные не удаляются до успешного завершения и проверки ссылок.
- Из книжных AI settings извлекаются модельные конфигурации, prompts и speech settings.
- Из глобального UI создаётся исходный UI profile; все существующие книги получают его, сохраняя нынешний вид.
- Из image settings создаются раздельные исходные Image и Video profiles с распределением favorite models по поддерживаемым задачам.
- Credentials извлекаются из глобальных и книжных настроек, вложенных provider configurations, speech и images.
- Нельзя считать все подключения одного provider одинаковыми: у них могут различаться endpoint, key и account.
- Нельзя молча выбрать один ключ из нескольких различных. Нужны сохранение всех конфигураций и понятное сопоставление, либо экран разрешения конфликтов. **Сейчас:** legacy книжный record сохраняется в local-only `meta`; активная глобальная connection не перезаписывается. Экрана восстановления/сопоставления нет, поэтому этот пункт не закрыт.
- Идентичные безопасно нормализованные профили можно объединить; разные остаются отдельными, например `Imported · <название книги>`.
- Старые prompts мигрируют в пользовательские presets. По текущему снимку не всегда возможно определить, из какого preset они когда-то были скопированы.
- Различия `Read aloud after generation` между книгами сохраняются через разные TTS-профили, даже если модель/voice совпадают.
- Существующие snapshots чатов сохраняются. Новая роль Character chat не переназначает модели уже созданных character chats.

### 10.2. Переносимость

Одних profile IDs в `.arcbook` недостаточно: на другом устройстве библиотека может отсутствовать.

Контракт `.arcbook` **v4**, представленный в текущем encoder/decoder:

- включать книжные selections и определения используемых text/TTS/STT/Image/Video/UI profiles, Story/Codex/Summary presets, а также зависимые Chat/Character presets и custom themes UI-профиля; не переносить всю глобальную библиотеку/default assignments;
- **не включать connections вообще**: ни credentials, ни endpoints, ни accounts, ни локальные connection IDs, ни credential/connection fingerprints;
- очищать connection-related поля также в snapshots/jobs и вложенных metadata; provider/model identity можно сохранять для работы с локально настроенным сервисом. Character speaker tokens и story-boundary content fingerprints — не credentials/connection fingerprints и сохраняют отдельный смысл;
- обычный import remaps книжные и профильные IDs, создаёт новую книгу и независимые профильные определения; pending proposals становятся stale, paid jobs не возобновляются;
- при установке sync definitions свободный ID или идентичное определение переиспользуется; несовпадающий занятый ID клонируется с remapping ссылок. Повторная установка может переиспользовать идентичный предыдущий conflict clone; чужой общий профиль не перезаписывается, совпадение имени не является сопоставлением;
- при отсутствии локальной настройки провайдера обозначать Setup required, не создавая connection из backup и не заменяя модель;
- сохранить импорт прежних архивов и обновить schema validation/remapping новых ссылок;
- исключать ключи из archive, диагностик и логов по явной схеме, не только по совпадению имени поля с `apiKey`.

**Sync:** использует тот же безопасный archive contract, без connections. Connected import/pull сохраняет книжные IDs и переносимые definitions; при чтении selections они устанавливаются через `importSettingsProfiles()`, с conflict clones вместо перезаписи общих объектов. Это изоляция изменений одной книги, не полная cross-device синхронизация библиотеки. Decoder принимает версии 1–4; encoder использует v4 при наличии profiles (legacy payload без них — v2, либо v3 с video). См. [CODEX_ILLUSTRATIONS.md](CODEX_ILLUSTRATIONS.md).

Профили в `localStorage` и книжные records в IndexedDB не образуют единую транзакцию. Ошибка импорта может оставить неиспользуемые установленные профили; полную атомарность и завершённую проверку import/sync не заявляем. Очистка metadata не удаляет секреты, вручную вписанные в текст документов/промптов.

### 10.3. Cache и media jobs

Глобальные настройки audio cache уже существуют, но идентичность cache учитывает книгу. Перенос панели в глобальные Settings не требует cross-book deduplication и не должен менять ownership/очистку аудио.

Для media jobs сохраняем устойчивые ссылки и параметры. Переименование alias или правка профиля не должны менять уже созданную задачу. Смена credentials/account для продолжаемой задачи требует явной проверки, а не скрытого fallback.

## 11. Дальнейшая интеграция и проверка

Продуктовые уточнения закрыты; повторное согласование connection и варианта A не требуется. Storage/resolver, редакторы, книжные selections и archive v4 уже присутствуют в рабочем дереве.

1. Автоматически проверены профили/defaults, previews, snapshots чатов, сохранение drafts, navigation/save guards и возврат к последнему document/chat после перезапуска.
2. Закрыть пользовательское восстановление/сопоставление legacy credentials без потери recovery data и скрытого выбора account. Recovery data сохранены локально; редактора сопоставления пока нет.
3. Автоматически проверены archive v1–v4, сохранение legacy response length, profile conflict clones, ошибки сохранения и media connection guards. Проверить перенос реальной библиотеки между браузерами вручную; localStorage и IndexedDB не имеют общей транзакции.
4. Проверить keyboard/mobile UX вручную; cursor/scroll/focus не входят в текущий контракт last-book location.
5. Регрессионные проверки Story/Summary подтверждают: изменение профиля или активного подключения во время catalog lookup не подменяет снимок уже готовящегося запроса.

## 12. Критерии готовности

Отмечены критерии, подтверждённые реализацией и автоматическими проверками. Неотмеченные пункты требуют дополнительной ручной проверки или отдельного recovery UI; полный пользовательский acceptance не заявляется.

- [x] Глобальные Settings доступны из Home и рядом с Home в левом пространстве книги.
- [x] В книге ровно две вкладки настроек: Profiles и Context.
- [x] Profiles не содержит credentials и подробных редакторов.
- [x] Каждый выбранный профиль/preset имеет рабочий Edit, открывающий конкретный объект.
- [x] Возврат сохраняет книгу, document/chat и рабочие drafts; Back to last book работает и после входа из Home.
- [x] Изменение text model profile влияет на все связанные книги после Save.
- [x] Duplicate позволяет одной книге отделиться от общего профиля.

## 13. Закрытые уточнения и оставшиеся границы

1. **Text connection подтверждена:** одна активная глобальная connection для всех text profiles/ролей. Внутри text profile нет выбора connection; Connections не становятся библиотекой именованных подключений.
2. **Источник чата подтверждён — A:** роли Chat/Character chat выбранного книгой text profile. Вариант B (всегда глобальный default text profile) отклонён. Отдельного книжного Chat selector нет; сохранённый snapshot и ручные настройки чата остаются независимыми.

Типы профилей, живые книжные presets, явный Save с предупреждением, response length/reveal speed, defaults и запрет connections в backup также не требуют повторного согласования. Оставшаяся работа — recovery UX и ручная проверка контракта (разделы 3, 11 и 12), не открытые продуктовые вопросы.
